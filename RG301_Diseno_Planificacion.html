    RG301: Diseño de la solución y planificación¶

    Resultado de Aprendizaje: RA2 - Planificar actividades, recursos, riesgos y cronograma del proyecto.

    Objetivo: Diseñar la solución técnica completa del proyecto, planificar todas las actividades, recursos y riesgos, y crear un cronograma detallado que permita ejecutar el proyecto de forma organizada.

    Modalidad: Trabajo en grupos de 2-3 personas

    Puntuación: 30 puntos

    Tareas¶

    1. RA2.1 - Diseño de la arquitectura¶

    • Crear diagrama de arquitectura de infraestructura (Docker o AWS según reto)
    • Diseñar topología de red
    • Definir servicios y componentes necesarios
    • Documentar decisiones de diseño

    Herramientas recomendadas:

    • draw.io (gratuito)
    • Lucidchart (freemium)
    • Miro (freemium)
    • Excalidraw (gratuito)
    • PlantUML (gratuito)

    2. RA2.2 - Diseño de base de datos¶

    • Crear modelo de datos (diagrama entidad-relación)
    • Definir tablas principales y relaciones
    • Documentar estructura de base de datos
    • Planificar scripts de inicialización

    3. RA2.3 - Diseño de aplicación web¶

    • Definir estructura y funcionalidades del sitio web
    • Crear mockups o wireframes (opcional)
    • Definir tecnologías y herramientas
    • Planificar desarrollo de componentes

    4. RA2.4 - Descomposición del trabajo¶

    EDT/WBS

    EDT (Estructura de Desglose del Trabajo) o WBS (Work Breakdown Structure) es una descomposición jerárquica del proyecto en fases, entregables y tareas, que facilita la planificación, la asignación de responsabilidades y el seguimiento del avance.

    • Crear estructura de desglose del trabajo (EDT/WBS)
    • Identificar todas las actividades necesarias
    • Identificar dependencias entre actividades
    • Estimar esfuerzo para cada actividad

    Herramientas recomendadas:

    • Trello (gratuito)
    • Microsoft Planner (gratuito con cuenta educativa GVA)
    • Asana (freemium)
    • Notion (freemium)
    • Jira (freemium)

    5. RA2.5 - Planificación temporal¶

    • Crear cronograma detallado con fechas
    • Definir hitos y entregables
    • Asignar fechas límite a actividades
    • Identificar ruta crítica

    Herramientas recomendadas:

    • Microsoft Project (de pago, disponible con MS365 educativo)
    • GanttProject (gratuito, open source)
    • ProjectLibre (gratuito, open source)
    • Smartsheet (freemium)
    • Microsoft Excel / Google Sheets con plantillas de Gantt (gratuitos)
    • Trello con power-ups de Gantt (gratuito)

    6. RA2.6 - Gestión de recursos¶

    • Asignar roles y responsabilidades al equipo
    • Identificar herramientas necesarias
    • Verificar disponibilidad de recursos
    • Planificar acceso a servicios (AWS, GitHub, etc.)

    Herramientas recomendadas:

    • Microsoft Planner (gratuito con cuenta educativa GVA)
    • Trello (gratuito)
    • Asana (freemium)
    • Monday.com (freemium)
    • Notion (freemium)

    7. RA2.7 - Análisis de riesgos¶

    • Identificar riesgos del proyecto
    • Evaluar probabilidad e impacto
    • Crear matriz de riesgos
    • Definir estrategias de mitigación

    Herramientas recomendadas:

    • Microsoft Excel / Google Sheets (gratuitos)
    • Notion (freemium)
    • Trello (gratuito)
    • Plantillas de gestión de riesgos en Microsoft Planner

    8. RA2.8 - Configuración de herramientas de planificación¶

    • Configurar tablero en Trello o Microsoft Planner
    • Crear tareas para todas las actividades
    • Asignar responsables y fechas
    • Configurar etiquetas y categorías

    Entregables¶

    1. Documento de diseño¶

    El documento de diseño debe incluir:

    • Diagrama de arquitectura de infraestructura
    • Diagrama de modelo de datos
    • Especificación de diseño de aplicación web
    • Documentación de decisiones de diseño

    Formato: Documento en Markdown o PDF, subido al repositorio del proyecto.

    2. Documento de planificación¶

    El documento de planificación debe incluir:

    • Estructura de desglose del trabajo (EDT/WBS)
    • Cronograma detallado (diagrama de Gantt o tabla)
    • Matriz de asignación de recursos
    • Matriz de riesgos con estrategias de mitigación

    Formato: Documento en Markdown o PDF, subido al repositorio del proyecto.

    3. Tablero de planificación¶

    El tablero de planificación debe estar configurado con:

    • Tablero en Trello o Microsoft Planner configurado
    • Todas las tareas creadas y organizadas
    • Responsables asignados
    • Fechas de vencimiento establecidas

    Formato: Enlace compartido al tablero (Trello o Microsoft Planner) con permisos de lectura para los profesores.

    4. Presentación del diseño y planificación¶

    La presentación debe incluir:

    • Presentación PowerPoint de 10-15 minutos
    • Incluye diagramas de arquitectura
    • Incluye cronograma y planificación
    • Demuestra comprensión del diseño y planificación

    Formato: Archivo PowerPoint o PDF, subido al repositorio del proyecto.

    Evaluación¶

    Puntuación total: 30 puntos

    Consulta la rúbrica de corrección para conocer los criterios y niveles de desempeño con los que se calificará este reto.

    La evaluación se realizará mediante:

    • Revisión del documento de diseño (8 puntos)
    • Calidad y completitud de los diagramas de arquitectura
    • Diseño del modelo de datos
    • Especificación de la aplicación web

    • Documentación de decisiones

    • Revisión del documento de planificación (10 puntos)

    • Estructura EDT/WBS completa y detallada
    • Cronograma realista y bien temporalizado
    • Matriz de recursos completa

    • Análisis de riesgos y estrategias de mitigación

    • Revisión del tablero de planificación (6 puntos)

    • Configuración adecuada del tablero
    • Tareas completas y bien organizadas
    • Asignación de responsables

    • Fechas de vencimiento establecidas

    • Presentación del diseño y planificación (6 puntos)

    • Claridad y estructura de la presentación
    • Calidad de los diagramas mostrados
    • Comprensión del diseño y planificación
    • Capacidad de explicar y defender las decisiones tomadas

    Criterios de evaluación¶

    Este reto evalúa los siguientes criterios del RA2:

    • RA2.1: Diseño de la arquitectura
    • RA2.2: Diseño de base de datos
    • RA2.3: Diseño de aplicación web
    • RA2.4: Descomposición del trabajo
    • RA2.5: Planificación temporal
    • RA2.6: Gestión de recursos
    • RA2.7: Análisis de riesgos
    • RA2.8: Configuración de herramientas de planificación

    Fecha de entrega¶

    La fecha de entrega será establecida por el profesorado y comunicada a través de Aules.

    Importante

    Todos los entregables deben estar disponibles en el repositorio del proyecto antes de la fecha límite establecida.
